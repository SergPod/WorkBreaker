   [x] Когда отсрочка отзвонила (FCountdown = 0) — FPostponing сбрасывается

   [x] Отложить можно каждый раз, когда показывается окно перерыва:

ТЕХНИЧЕСКИЕ ЗАМЕЧАНИЯ
---------------------

* Все три формы — НОРМАЛЬНЫЕ дизайнерские формы (.lfm + {$R *.lfm}),
  создаются через Application.CreateForm в tbreak.lpr. CreateNew /
  CreateBreak / конструкторы-фабрики больше НЕ используются (остались
  только закомментированные остатки).
* Порядок создания форм в tbreak.lpr ВАЖЕН: сначала TMainForm (TrayApp),
  потом TBreakFormRs (BreakForm) и TSettingsFormRs (SettingsForm) —
  FormCreate BreakForm присваивает OnFinish := TrayApp.BreakFinished.
* RequireDerivedFormResource := True в tbreak.lpr — .lfm обязателен.
* Точка входа: Application.ShowMainForm := False, MainFormOnTaskbar := False.
* GetLastInputInfo: ОБЯЗАТЕЛЬНО по указателю (@Info), не by-value.
  Динамический GetProcAddress, нет статического external.
  (В FPC "var" в external-декларации передаётся by value — AV.)
* TSpinEdit из юнита Spin (не ComCtrls, не StdCtrls).
* Подменю TMenuItem: дочерние TMenuItem добавляются через MenuPause.Add(Item)
  в FormCreate. Свойство .Menu у TMenuItem только read.
* Иконка трей-меню: LoadImage с LR_LOADFROMFILE из tbreak.ico рядом с exe;
  HICON передаётся TIcon.Handle (TIcon забирает владение), потом Assign в
  TrayIcon.Icon. Фолбэк — MakeIntResource(1) из ресурсов.
* Postpone: окно перерыва СКРЫВАЕТСЯ (не остаётся на экране!), отсчёт идёт
  в MainForm (FCountdown := PostponeSec, FPostponing = True). BreakForm
  переиспользуется, FPostponed сбрасывается только в Start.
* MenuSkip.Enabled / MenuPostpone.Enabled зависят от InBreak;
  MenuNewMini/MenuNewLong — от (InBreak or FPostponing).
* Состояние «идёт перерыв» живёт у диспетчера: TMainForm.FInBreak
  (ставится в ShowBreak, сбрасывается в BreakFinished). TBreakKind =
  (bkMini, bkLong) — bkNone УБРАН: окно перерыва знает только два вида
  и show/hide; «перерыва нет» — состояние диспетчера, не окна.
* ИСПРАВЛЕНО (баг Skip/Postpone): BreakFinished теперь сбрасывает
  FInBreak := False после Hide. Раньше флаг залипал True (New mini/long
  запрещены, Skip/Postpone активны), а TimerTick каждый тик звал
  BreakForm.Tick -> OnFinish -> BreakFinished и обнулял FCountdown :=
  FMiniInterval, из-за чего следующий перерыв не наступал. Сброс — во всех
  путях завершения (Skip, Postpone, Esc, Alt+F4, естественное окончание),
  т.к. все они идут через OnFinish.
* ИСПРАВЛЕНО (двойной таймер): FormCreate создавал второй TTimer поверх
  таймера из .lfm — TimerTick срабатывал дважды за секунду, все отсчёты
  шли в 2 раза быстрее. Теперь ходит только таймер из mainform_rs.lfm.
* ИСПРАВЛЕНО (Alt+F4 убивает форму): FormCloseQuery BreakFormRs звал OnFinish,
  но не ставил CanClose := False — LCL уничтожал форму, глобальная BreakForm
  становилась висячей ссылкой, следующий перерыв → AV. Теперь CanClose :=
  False: форма только прячется и переиспользуется.
* ИСПРАВЛЕНО (меню залипало после отсрочки): когда отложенный отсчёт
  доходит до нуля, FPostponing сбрасывается + UpdateMenu в том же тике;
  аналогично при аннулировании отложенного перерыва через IdleReset.
  Раньше "New mini/long" оставались заблокированными до секунды (или весь
  интервал в случае простоя).
* Окно перерыва всегда сверху: fsStayOnTop даёт WS_EX_TOPMOST, но он держит
  окно выше только НЕ-topmost окон; свежеактивируемое topmost окно (меню,
  диалоги, другие приложения) может его перекрыть. Поэтому KeepOnTop
  (SetWindowPos(Handle, HWND_TOPMOST, ..., SWP_NOMOVE|SWP_NOSIZE|
  SWP_NOACTIVATE)) вызывается в OnDeactivate и в Tick. SWP_NOACTIVATE
  обязателен — иначе окно перерыва у тянет фокус на себя.
* MenuSettings: добавлен в mainform_rs.lfm (TrayMenu), OnClick =
  MenuSettingsClick -> окно настроек TSettingsFormRs открывается из UI,
  OK сохраняет INI. Пункт Settings НЕ входит в UpdateMenu (не зависит от
  InBreak / паузы).
* РЕLEASE-СБОРКА: стандартный Release-режим Lazarus использует -O3.
  В FPC 3.2.2 оптимизация O3 ломает это приложение (тихий крах exe при
  запуске из ОС, без ошибок компиляции; Debug-сборка работает). Решение:
  в Release-режиме поставить Optimization Level = 1 (O1).
  Project → Project Options → Build Mode: Release → Code Generation →
  Optimization Level: 1.
* ПЕРЕИМЕНОВАНО: проект WorkBreaker, старый бренд "Stretchly Mini" убран
  из кода — INI-файл 'WorkBreaker.ini' (миграция со старого имени НЕ
  делается, старый stretchly_mini.ini можно удалить вручную), hint трея
  "WorkBreaker - ...", Caption главной формы 'WorkBreaker'. Термины
  mini/long break — функциональные, не переименованы.
* ИСПРАВЛЕНО (баг "только длинные перерывы"): FCountMini рос монотонно и
  после достижения FLongInterval условие long break выполнялось навсегда.
  Теперь TimerTick сбрасывает FCountMini := 0 при показе длинного перерыва.
  Ручной "New long break" из меню счётчик НЕ сбрасывает (сброс только в
  автоматическом пути TimerTick).
